# 乗務記録ドメインモデル・永続化基盤 設計

## 目的

乗務員日報、乗降地自動記録、GPS欠損補完の後続機能が利用できる、乗務セッション・営業・イベントの共通基盤を追加する。今回の成果物は、ドメインモデルをRoom/SQLiteへ保存し、再読込できるAndroidアプリ内の境界までとする。

## 対象モデル

- `DutySession`: 乗務の識別子、開始・終了日時、営業一覧、イベント一覧を持つ。
- `Trip`: 乗車・降車日時、乗車地・降車地、乗車人数、営業距離（m）、運賃（円）、追加料金（円）、支払区分、備考を持つ。
- `DutyEvent`: 識別子、イベント種別、発生日時、任意の記録場所、備考を持つ。種別は `出庫`、`入庫`、`乗車`、`降車`、`回送開始`、`回送終了`、`休憩開始`、`休憩終了` を表現する。
- `RecordedPlace`: 緯度、経度、精度（m）、取得日時、住所文字列、住所精度、位置取得元を持つ。住所が未解決でも座標情報を保持できるよう、住所関連値は nullable とする。

識別子は `String`、日時は `java.time.Instant`、距離・人数・金額はそれぞれ `Long`/`Int`/`Long` とする。支払区分は現時点の代表値を列挙型で表現し、未指定を許容する。ドメインモデルはAndroid/Room型に依存しない。

## 逆ジオコーディング境界

`ReverseGeocoder` はドメイン側のインターフェースとして、緯度・経度から `RecordedPlace` の住所情報を補完する契約だけを定義する。国土地理院API、GPS取得、トンネル補完は今回実装しない。

## 永続化

Room Entity は `duty_sessions`、`trips`、`duty_events` の3テーブルとする。`RecordedPlace` はTripの乗車地・降車地、およびイベントの任意場所を各テーブルへ埋め込み、座標・精度・取得日時・取得元・住所精度・住所文字列を別列で保存する。セッションIDを外部キーとして営業・イベントを関連付け、削除時は子レコードも削除する。

RoomのTypeConverterで `Instant` と列挙型を文字列/数値へ変換する。`DutyRecordRepository` はドメインモデルを受け取り、`save(session)` と `findById(id)` で保存・再構成を提供する。再読込時の営業・イベント順は発生日時の昇順とする。

## 非対象

UIへの乗務記録画面追加、国土地理院API通信、GPSセンサー連携、トンネル内の位置補完、PDF日報出力、FareCalculatorの変更は行わない。FareCalculatorは既存どおりGPS/DB非依存を維持する。

## 受け入れ条件

1. 4モデルと8種のDutyEventをKotlinの公開ドメイン型として利用できる。
2. 座標系の記録と住所未解決状態を保持できる。
3. 1つのセッションに複数の営業・イベントを保存し、Room/SQLiteから同じ内容を再読込できる。
4. `ReverseGeocoder` は実装クラスを持たず、FareCalculatorの依存関係に変化がない。
5. JVMテスト、Room in-memoryのinstrumentationテスト、debugビルドが成功する。
